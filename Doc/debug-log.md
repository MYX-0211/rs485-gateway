# 调试复盘与踩坑记录（Debug Log）

> 本项目开发中真实遇到并解决的问题复盘（现象 → 根因 → 解决）。配套项目 [pid-gateway](https://github.com/MYX-0211/pid-gateway) 也有同款记录。

## 1. HAL_Delay 卡死 —— CubeMX timebase 中断未使能

- **现象**：上电后程序卡在 HAL_Delay / 无输出
- **根因**：CubeMX 生成的 TIM6 中断未在 NVIC 使能，uwTick 永远不增长，所有依赖超时的 HAL 调用永久等待
- **解决**：手动「清 pending → 优先级 0 → NVIC 使能」（该中断不触碰 RTOS API，优先级 0 安全）
- **面试口径**：HAL timebase 是 HAL 层的心脏，TIM6 中断没使能 = HAL_Delay/HAL_GetTick 全线停摆

## 2. printf 多任务打印交错

- **现象**：多任务并发 printf 输出相互穿插、脏行
- **根因**：UART2 发送非原子，任务切换打断半个字符串
- **解决**：`fputc` 经互斥锁串行化；调度器启动前自动降级裸发（此时无并发）
- **面试口径**：重定向 printf 必须加锁，且要处理"调度器未启动"的空窗

## 3. ESP-01S 配网阻塞启动

- **现象**：ESP 配网/TCP 重试最坏数十秒，期间系统其它任务起不来
- **根因**：网络初始化放在主流程同步执行
- **解决**：配网与 TCP 重试放入低优先级网络任务后台执行，调度器与 OLED 立即启动
- **面试口径**：慢速外设初始化应异步化，别阻塞调度器与关键任务

## 4. UART 丢字节下的 AT 应答解析

- **现象**：偶发丢字节导致 AT 应答匹配失败、状态机错乱
- **根因**：单关键字精确匹配对丢字节脆弱
- **解决**：多关键字匹配 + 安全重试（键序：退出透传 → 复位 → 探测 → 配网 → TCP）
- **面试口径**：串口 AT 交互要按"状态机 + 容错重试"设计，不能假设链路无损

## 5. 栈/堆耗尽定位

- **现象**：偶发跑飞、死机无输出
- **解决**：使能 `configCHECK_FOR_STACK_OVERFLOW` + malloc 失败钩子，爆栈/堆耗尽时打印任务名并停机，一次定位到任务
- **面试口径**：FreeRTOS 爆栈钩子是定位"偶发死机"的第一手段

## 6. 双通道验证习惯

- 外部链路（ESP/串口/总线）结论坚持"设备侧现象 + 本机日志"双向核对，不只看一侧
